# Equipoise Cloud Deployment Guide (Render)

This document provides complete, step-by-step instructions for deploying Equipoise to [Render](https://render.com) using the included Blueprint specification (`render.yaml`).

---

## 1. Overview & Architecture

Equipoise is deployed as three managed components on Render:
1. **Database**: Managed PostgreSQL 17 (`equipoise-postgres`).
2. **Backend**: Spring Boot 4 / Java 25 Web Service (`equipoise-backend`), running with `SPRING_PROFILES_ACTIVE=prod` and monitored at `/actuator/health`.
3. **Frontend**: React + Vite + Tailwind containerized with Nginx (`equipoise-frontend`), communicating with the backend over HTTPS.

---

## 2. Step-by-Step Render Deployment

### Step A: Connect Repository
1. Log in to your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** and select **Blueprint**.
3. Connect your GitHub repository (`equipoise`).
4. Render will parse `render.yaml` automatically and display the three services to be provisioned:
   - `equipoise-postgres` (PostgreSQL Database)
   - `equipoise-backend` (Docker Web Service)
   - `equipoise-frontend` (Docker Web Service)

### Step B: Review Environment Variables
Render auto-wires the database connection string and cross-service hosts. Review and customize optional variables if needed:

| Service | Environment Variable | Required | Description |
|---|---|---|---|
| `backend` | `SPRING_PROFILES_ACTIVE` | Yes | Set to `prod` |
| `backend` | `SPRING_DATASOURCE_URL` | Yes | Auto-populated from `equipoise-postgres` connection string |
| `backend` | `SPRING_DATASOURCE_USERNAME` | Yes | Auto-populated from `equipoise-postgres` user |
| `backend` | `SPRING_DATASOURCE_PASSWORD` | Yes | Auto-populated from `equipoise-postgres` password |
| `backend` | `JWT_SECRET` | Yes | Auto-generated by Render (`generateValue: true`) or custom 32+ character key |
| `backend` | `CORS_ALLOWED_ORIGINS` | Yes | Set to `https://{frontend-host}` |
| `backend` | `SLACK_WEBHOOK_URL` | Optional | Incoming Slack webhook for critical alert dispatch |
| `backend` | `SMTP_HOST` | Optional | SMTP host for email notifications (e.g. `smtp.sendgrid.net`) |
| `backend` | `SMTP_PORT` | Optional | SMTP port (default `587`) |
| `backend` | `SMTP_USERNAME` | Optional | SMTP username |
| `backend` | `SMTP_PASSWORD` | Optional | SMTP password |
| `backend` | `MAIL_FROM` | Optional | Sending address (e.g. `notifications@yourdomain.com`) |
| `backend` | `JIRA_BASE_URL` | Optional | Jira Cloud URL (`https://yourcompany.atlassian.net`) |
| `backend` | `JIRA_EMAIL` | Optional | Jira user email address |
| `backend` | `JIRA_API_TOKEN` | Optional | Jira REST API token |
| `backend` | `ICAL_FEED_URL` | Optional | Calendar out-of-office iCal feed URL |
| `frontend`| `VITE_API_URL` | Yes | Auto-populated to `https://{backend-host}/api` |
| `frontend`| `VITE_USE_MOCK` | Yes | Set to `"false"` to utilize the Spring Boot REST backend |

### Step C: Deploy
1. Click **Apply**.
2. Render provisions the PostgreSQL instance first.
3. Once the database is ready, the backend builds and executes its initial schema migration, followed by the frontend build.
4. Verify backend health: `https://<backend-url>/actuator/health` returns `{"status":"UP"}`.

## 3. Demo Manager Account & Initial Seeding

When the PostgreSQL database is first created and empty, `DataInitializer` seeds default teams, initial projects, and demo users automatically:

- **Manager Account**:
  - **Email**: `manager@equipoise.com`
  - **Password**: `Password@123`
  - **Role**: `MANAGER`
- **Admin Account**:
  - **Email**: `admin@equipoise.com`
  - **Password**: `Password@123`
  - **Role**: `ADMIN`

> **Note**: `DataInitializer` seeds only when `users.count() == 0`. Once initial accounts are created, subsequent startups will not overwrite or reseed data.

## 4. Continuous Deployment & Deploy Hook

The GitHub Actions workflow [cd.yml](file:///.github/workflows/cd.yml) builds and pushes production images to GitHub Container Registry (`ghcr.io`) on every push to `main`.

To trigger automatic deployment on Render after images publish:
1. In the Render Dashboard, navigate to `equipoise-backend` > **Settings** > **Deploy Hook**.
2. Copy the deploy hook URL (e.g., `https://api.render.com/deploy/srv-xxxx?key=yyyy`).
3. In your GitHub repository, go to **Settings** > **Secrets and variables** > **Actions**.
4. Create a new repository secret named `RENDER_DEPLOY_HOOK_URL` and paste the URL.
5. If `RENDER_DEPLOY_HOOK_URL` is omitted, the CD workflow skips deployment trigger silently.

## 5. Rollback Procedures

If an issue occurs after a deployment:
1. **Rollback via Render Dashboard**:
   - Navigate to `equipoise-backend` or `equipoise-frontend`.
   - Go to the **Deploys** tab.
   - Locate the previous successful deploy and select **Rollback to this deploy**.
2. **Rollback via Git**:
   - Revert the commit on the `main` branch:
     ```bash
     git revert HEAD
     git push origin main
     ```
   - GitHub Actions CD will build the prior commit and re-trigger Render.
3. **Database Restore**:
   - Render automatically takes daily backups of PostgreSQL.
   - Go to `equipoise-postgres` > **Backups** to restore to a specific point in time if needed.
